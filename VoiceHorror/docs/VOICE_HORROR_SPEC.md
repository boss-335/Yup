# Voice Horror (اسم مؤقت) — وثيقة التصميم والتنفيذ

> **الحالة:** فكرة معتمدة للنموذج الأولي — نسخة 0.1
> **الغرض:** مرجع تطوير لـ Claude Code
> **المنصة المستهدفة:** PC (Windows) — التطوير على macOS
> **المحرك:** Unity 6 LTS، C#، Scripting Backend: Mono

---

## 0. تعليمات لـ Claude Code (اقرأها أولاً)

1. **اشتغل مرحلة مرحلة** (القسم 8). لا تبدأ مرحلة جديدة قبل ما المستخدم يأكد أن معايير قبول المرحلة الحالية نجحت.
2. **أنت ما تقدر تفتح Unity Editor.** لذلك:
   - اكتب كل شيء كسكربتات وملفات نصية (C#، ScriptableObject defaults، JSON).
   - لكل مشهد اختبار، اكتب **Editor script** يبني المشهد من قائمة `Tools/VoiceHorror/Build <Scene>` بدل ما تطلب من المستخدم يركّبه يدوياً.
   - في نهاية كل مهمة، اكتب للمستخدم **خطوات الاختبار اليدوي** بالضبط (أي قائمة يضغط، وش المتوقع يشوف ويسمع).
3. **نواة معالجة الصوت (DSP) مكتبة C# نقية** بدون أي اعتماد على `UnityEngine`، حتى تنختبر بـ `dotnet test` خارج Unity (القسم 6.2). هذا يخليك تتحقق من صحة الخوارزميات بنفسك.
4. **لا تضيف أي package** (Asset Store، NuGet، UPM) بدون موافقة المستخدم.
5. **كل قيمة قابلة للضبط** تكون في ScriptableObject أو ثابت مسمّى، مو رقم سحري داخل الكود.
6. **الصوت لا يغادر جهاز اللاعب أبداً.** لا رفع، لا تسجيل خارج `Application.persistentDataPath`.
7. اكتب commit واضح لكل خطوة منطقية.

## 1. الفكرة

لعبة رعب منظور أول على الـ PC، **الميكروفون إلزامي**.

- **صوتك خطرك:** أي صوت عالي تسويه في الواقع، المخلوقات تسمعه وتعرف مكانك وتهجم.
- **صوتك سلاحك:** كل سلاح مربوط بـ **أغنية أو عبارة سجّلتها أنت** في بداية اللعبة. عشان تطلق السلاح لازم تغنيها أو تقولها، وأنت خايف.
- **التوازن:** لازم تصدر صوت عشان تهاجم، لكن كل صوت يكشفك. فتحتاج **تزن صوتك**: تغني بدقة وبأخفض صوت ممكن.

### 1.1 الأعمدة (Pillars)
1. **الصوت سلاح وخطر في نفس اللحظة.** أي ميزة تفصل بينهم تُرفض.
2. **اللعبة تحكم على السلوك الفعلي، مو على الادعاء.** الصوت الحقيقي هو اللي يحسب.
3. **العدل الصوتي:** التقييم يقيس شكل اللحن والإيقاع، **مو جودة الصوت ولا طبقته**. الصوت الغليظ والرفيع اللي يسوون نفس المنحنى ياخذون نفس الدرجة.
4. **الخوف جزء من الآلية:** المرجع مسجّل وأنت هادئ، والأداء يصير وأنت متوتر. التسامح في التقييم مضبوط بحيث هذا الفرق يخلق توتر، مو ظلم.

### 1.2 الحلقة الأساسية
```
استكشاف بصمت ← مخلوق يقترب ← قرار: اختبئ أو هاجم
   ← تهاجم = تغني/تقول عبارة السلاح (نافذة أداء) ← الصوت يرفع "الخطر"
   ← دقة الأداء = الضرر | شدة الصوت = مدى السمع ← نجاة أو موت
```

## 2. الأنظمة الأساسية

### 2.1 التقاط الميكروفون (MicCapture)
- `Microphone.Start(device, loop: true, lengthSec: 2, frequency)` مع ring buffer، وقراءة العينات الجديدة كل frame عبر `Microphone.GetPosition`.
- معدل العينات: `AudioSettings.outputSampleRate` إذا يدعمه الجهاز، وإلا 48000 ثم 44100.
- اختيار الجهاز من قائمة `Microphone.devices` في الإعدادات، مع حفظ الاختيار.
- **macOS:** Unity Editor يحتاج إذن الميكروفون من System Settings ← Privacy & Security ← Microphone. اذكر هذا في خطوات الاختبار.
- معالجة حالات: ما فيه ميكروفون، الميكروفون انفصل أثناء اللعب ← إيقاف مؤقت مع رسالة.

### 2.2 المعايرة (Calibration)
تُشغّل أول مرة وقابلة للإعادة من الإعدادات. ثلاث مراحل:

| المرحلة | التعليمات للاعب | المدة | ما نقيسه |
|---|---|---|---|
| الصمت | "اسكت تماماً" | 3 ث | `noiseFloorDb` = النسبة المئوية 20 لـ RMS بالـ dBFS |
| الكلام العادي | "اقرأ هذي الجملة بصوتك العادي" | ~4 ث | `talkDb` = الوسيط للإطارات المصوّتة |
| الصوت العالي | "قلها بصوت عالي (مو صراخ)" | ~3 ث | `loudDb` = النسبة 90 |

- **كل الحدود تُحسب نسبياً** لهذي القيم، مو بقيم مطلقة.
- فحوص جودة: إذا `talkDb - noiseFloorDb < 10 dB` ← رسالة "البيئة مزعجة أو الميكروفون بعيد".
- حفظ النتيجة في `CalibrationProfile` (JSON في `persistentDataPath`).

### 2.3 مستويات الصوت (VoiceLevel)
من شدة الصوت الحالية بالنسبة للمعايرة:

| المستوى | الشرط (افتراضي، قابل للضبط) | مدى السمع |
|---|---|---|
| Silent | أقل من `noiseFloor + 4 dB` | 0 |
| Whisper | حتى منتصف المسافة بين floor وtalk | 3 م |
| Talk | حتى `talkDb + 3 dB` | 10 م |
| Loud | حتى `loudDb + 3 dB` | 25 م |
| Scream | فوق ذلك | كل الخريطة |

- مدى السمع **مستمر** (interpolation بين المستويات)، والمستويات للواجهة والتصحيح فقط.
- تنعيم: attack سريع (~50 ms)، release أبطأ (~300 ms) حتى ما يتذبذب.

### 2.4 الضجيج والخطر (NoiseSystem)
- كل frame اللاعب يُصدر `NoiseEvent { position, radius, loudness01, time }`.
- المخلوقات تشترك عبر `INoiseListener` وتقرر حسب المسافة (والإغلاق/الجدران لاحقاً).
- **مقياس الخطر (Threat)** 0–100 للاعب: يرتفع مع الضجيج ويتناقص مع الصمت. يتحكم في الموسيقى والإضاءة وسرعة ظهور المخلوقات.
- **واجهة إلزامية:** مؤشر صوت على الشاشة يبين المستوى الحالي وخط الخطر، حتى ما يحس اللاعب بالظلم.

### 2.5 المخلوقات (Creature AI) — MVP مخلوق واحد
حالات: `Idle → Investigate(lastNoisePos) → Hunt(player) → Search → Idle`
- تسمع الضجيج داخل مداه ← تروح لآخر مكان سمعته (مو مكان اللاعب الحالي).
- ضجيج مستمر أثناء Investigate ← تتحول Hunt.
- صمت لمدة `searchTimeout` ← ترجع Idle.
- الضرر يقطع Hunt مؤقتاً (stagger). NavMesh عادي.

### 2.6 الأسلحة (Weapons)

**التعريف (ScriptableObject `WeaponDefinition`):**
| الحقل | الوصف |
|---|---|
| `id`, `displayName` | |
| `referenceType` | `Melody` (أغنية/دندنة) أو `Phrase` (عبارة منطوقة) |
| `minDurationSec`, `maxDurationSec` | طول المقطع المسموح عند التسجيل |
| `baseDamage` | |
| `damageCurve` | AnimationCurve: الدرجة (0–100) ← مضاعف الضرر |
| `minScoreToFire` | تحت هذي الدرجة = فشل (بدون ضرر لكن الصوت انحسب) |
| `cooldownSec` | |
| `range`, `effectPrefab` | |

**مبدأ التوازن:** السلاح الأقوى له مقطع أطول ⇐ نافذة أداء أطول ⇐ ضجيج أكثر ⇐ خطر أكبر. وتقدر تغني بهمس بدقة عالية: ضرر أقل لكن أخفى.

**التسجيل (بداية اللعبة):**
1. اللاعب يختار لكل سلاح أغنية/دندنة أو عبارة.
2. يسجّلها **مرتين**. نتحقق من: الطول ضمن الحدود، مو هادئة جداً، مو مقطوعة (clipping)، والمرتين متشابهتين (درجة بينهم ≥ 60) وإلا نطلب إعادة.
3. نحفظ **الملامح المستخرجة فقط** (القسم 3.4)، مو الصوت الخام، إلا إذا فعّل اللاعب خيار "احفظ تسجيلاتي".

**الإطلاق (نافذة الأداء):**
1. اللاعب يضغط زر السلاح (مثلاً مطوّل على الماوس) ← تبدأ نافذة الأداء.
2. نسجّل حتى: صمت أطول من `endSilenceMs` (افتراضي 400) أو `maxDurationSec × 1.5`.
3. طوال النافذة، الضجيج ينحسب في NoiseSystem عادي.
4. بعد الانتهاء: تقييم ← درجة ← ضرر ← تأثير بصري وصوتي يعكس الدرجة.
5. MVP: التقييم بعد نهاية الأداء. لاحقاً: تقييم متدفق (subsequence DTW) للإطلاق المبكر.

## 3. تقييم الصوت (VoiceScoring) — قلب اللعبة

**المبدأ:** لا تقارن الموجة الخام أبداً. قارن **الملامح** بطريقة تتحمل اختلاف السرعة والطبقة والشدة.

### 3.1 الإطارات
- إطار 2048 عينة، قفزة 512 (عند 48 kHz: ~43 ms / ~10.7 ms). نافذة Hann.
- لكل إطار: `rmsDb`, `voiced`, `f0Hz`, `onsetStrength`، و(للعبارات) MFCC.

### 3.2 للألحان (Melody)
1. **استخراج النغمة:** YIN (threshold 0.15، نطاق 70–1000 Hz) ← `f0` لكل إطار + علامة `voiced`.
2. **تحويل لنصف نغمات:** `midi = 69 + 12·log2(f0/440)`.
3. **إزالة الطبقة:** اطرح الوسيط من كل القيم المصوّتة ⇐ اللحن نسبي (key-invariant).
4. **تنظيف:** median filter بطول 5، وتصحيح قفزات الأوكتاف (±12) المعزولة.
5. **المقارنة:** DTW بين المرجع والأداء على الإطارات المصوّتة، بقيد Sakoe-Chiba (20% من الطول)، والمسافة = فرق نصف النغمات مع سقف 3.
6. **الإيقاع:** ارتباط منحنى `onsetStrength` بعد المحاذاة بمسار DTW.

### 3.3 للعبارات (Phrase) — MVP
- MFCC (13 معامل، بدون المعامل الأول، مع CMN لكل مقطع) + DTW.
- **لاحقاً (قرار مفتوح):** تعرّف على الكلمات محلياً (Vosk يدعم العربي، أو Whisper صغير) للتحقق من المحتوى فوق النبرة.

### 3.4 الملامح المحفوظة للمرجع (`VoiceReference`)
```json
{
  "version": 1,
  "weaponId": "w_pistol",
  "type": "Melody",
  "sampleRate": 48000,
  "hop": 512,
  "takes": [
    { "pitchSemitones": [0.0, 0.1, null, 2.0], "onset": [0.1, 0.8, 0.2], "mfcc": null, "durationSec": 2.4 }
  ]
}
```
عند التقييم: قارن الأداء مع كل take وخذ **الأعلى**.

### 3.5 تحويل المسافة لدرجة
```
melodyScore = 100 · exp(-dtwDistNormalized / tauPitch)
rhythmScore = 100 · clamp01(onsetCorrelation)
finalScore  = wPitch·melodyScore + wRhythm·rhythmScore     (Melody)
finalScore  = 100 · exp(-mfccDtwNormalized / tauMfcc)      (Phrase)
```
افتراضيات أولية: `wPitch = 0.75`, `wRhythm = 0.25`. قيم `tau` تُعاير تجريبياً (القسم 7).
**عقوبة الطول:** إذا طول الأداء خارج 50%–200% من المرجع ← ضرب الدرجة في 0.5.

### 3.6 العدل (اختبارات إلزامية)
نفس اللحن يجب أن يأخذ درجة متقاربة (فرق ≤ 10) عند: نقله أوكتاف أو 5 نصف نغمات · تسريعه/تبطيئه 20% · خفض شدته 12 dB · إضافة ضجيج أبيض عند SNR 20 dB.
ولحن مختلف تماماً يجب أن يأخذ أقل من 40.

## 4. اللعب الجماعي (مرحلة لاحقة — لا تبنيه قبل M5)

- 2–4 لاعبين تعاوني.
- **دردشة قريبة (proximity voice):** حل جاهز (Photon Voice / Vivox / Dissonance) — **قرار مفتوح**.
- **ميزانية ضجيج مشتركة:** مقياس Threat واحد للفريق.
- **تخفيض الأصوات (ducking):** أثناء أداء لاعب لسلاحه، أصوات الباقين عنده تنخفض.
- **تسرّب الصوت (mic bleed):** إلغاء صدى + توصية بالسماعات + تجاهل الإطارات المتطابقة مع صوت الشبكة الخارج من السماعة.
- **مكافحة الغش:** التقييم محلي، الخادم يستلم الدرجة فقط، ويفرض حدود الضرر والـ cooldown.
- أدوار مقترحة: المغني (يطلق)، الحارس (يشتت)، المنسق (يوجّه بهمس).

## 5. الإعدادات والوصولية
- اختيار الميكروفون، إعادة المعايرة، حساسية إضافية (±6 dB).
- **زر كتم فوري** (push-to-mute) — يحتسب كصمت.
- **وضع البث (Streamer Mode):** إخفاء أسماء الأغاني، وتنبيه أن غناء أغاني محمية قد يسبب مطالبات حقوق على البث، مع اقتراح الدندنة أو عبارات خاصة.
- بديل للي ما يحب الغناء: دندنة أو عبارة منطوقة لكل سلاح.
- شاشة تصحيح (Debug overlay) تعرض: dB الحالي، المستوى، f0، آخر درجة وتفاصيلها.

### 6.2 مكتبة VoiceDsp (C# نقية)
- `asmdef` باسم `VoiceDsp` مع `noEngineReferences: true`، ونفس الملفات مُشار لها من مشروع `dsp-tests` (netstandard2.1 / xUnit).
- الواجهات:
```csharp
namespace VoiceHorror.Dsp {
  public readonly struct FrameFeatures { public float RmsDb; public bool Voiced; public float F0Hz; public float Onset; public float[] Mfcc; }
  public interface IFeatureExtractor { FrameFeatures[] Extract(float[] mono, int sampleRate); }
  public interface IPitchDetector { (bool voiced, float f0) Detect(float[] frame, int sampleRate); }
  public static class Dtw { public static (float dist, int[] pathA, int[] pathB) Align(float[] a, float[] b, float bandRatio); }
  public interface IVoiceScorer { ScoreResult Score(VoiceReference reference, FrameFeatures[] performance); }
  public struct ScoreResult { public float Final; public float Melody; public float Rhythm; public float LengthRatio; }
}
```
- الاختبارات تولّد إشارات صناعية (جيوب، سلالم نغمية، ضجيج) وتطبّق متطلبات القسم 3.6.

### 6.3 قواعد عامة
- Namespace جذري: `VoiceHorror`.
- لا تخصيص ذاكرة (allocations) في مسار الصوت كل frame: buffers مسبقة.
- ميزانية الأداء: معالجة الصوت كل frame < 2 ms على الماك، وتأخر مؤشر الصوت < 100 ms.
- Input System الجديد.

## 8. المراحل ومعايير القبول

### M0 — الميكروفون والمعايرة
- MicCapture + Calibration + VoiceLevel + مؤشر صوت + Debug overlay.
- مشهد `Tools/VoiceHorror/Build Mic Test`.
- **القبول:** المؤشر يتحرك بسلاسة مع الصوت، المستويات الخمسة تظهر صح بعد المعايرة، والمعايرة تنحفظ وتنحمّل.

### M1 — نواة التقييم (DSP)
- VoiceDsp: YIN، التحويل لنصف نغمات، DTW، onset، MFCC، الـ scorer.
- `dsp-tests` يمر بكل اختبارات القسم 3.6.
- مشهد `Score Lab`: سجّل مرجع، سجّل أداء، اعرض المنحنيين بعد المحاذاة والدرجة وتفاصيلها.
- **القبول:** نفس اللحن من المستخدم ≥ 70، لحن مختلف ≤ 40، دندنة بطبقة مختلفة ≥ 65.

### M2 — الأسلحة
- WeaponDefinition (سلاحين: قصير وطويل)، شاشة تسجيل المراجع، نافذة الأداء، دمية هدف تتلقى ضرر.
- **القبول:** الضرر يتناسب مع الدرجة، والفشل تحت الحد يعطي صفر، وتسجيل المراجع يرفض المقاطع الرديئة.

### M3 — الضجيج والمخلوق
- NoiseSystem + ThreatMeter + مخلوق واحد بحالاته + مستوى رمادي (greybox) صغير.
- **القبول:** الهمس ما يجذب المخلوق من بعيد، الكلام العادي يجذبه لآخر موقع، الصراخ يجيبه من أي مكان، والصمت يرجعه للتجوال.

### M4 — شريحة عمودية (Vertical Slice)
- مستوى واحد قصير (10 دقائق)، سلاحين، موت وفوز، صوت ومؤثرات أولية، شاشة إعدادات.
- **القبول:** جلسة كاملة من أول المعايرة حتى النهاية بدون أخطاء، و5 لاعبين خارجيين يفهمون الآلية بدون شرح.

### M5 — نموذج تعاوني (لاعبين)
- القسم 4 بحد أدنى: لاعبين، دردشة قريبة، Threat مشترك، ducking.

## 9. الخصوصية والقيود (ثابتة)
- معالجة الصوت محلية بالكامل. لا رفع لأي صوت أو ملامح.
- المراجع تنحفظ كملامح فقط افتراضياً، مع زر "احذف كل تسجيلاتي".
- في الجماعي، الصوت ينتقل فقط عبر حل الدردشة الصوتية، والتقييم ما يرسل إلا رقم.
- تنبيه أول تشغيل: اللعبة تستمع للميكروفون أثناء اللعب، وليش.
